---
description: 开发域：需求澄清 → 方案 → 拆解 → 实现 → 自检，可指定评审/测试/重构专项
argument-hint: <需求描述 | review | test | refactor>
---

按 wudi-dev 技能的全周期方法论处理 `$ARGUMENTS`：

1. 为空：提示用法（直接描述需求，或用 review / test / refactor 指定专项），并快速读 `.wudi/project.json` 报告项目档案是否就绪。
2. 需求描述：走「澄清 → 方案（2~3 个对比 + 推荐）→ 用户确认 → 拆解 → 实现 → 自检」，自检结果逐项如实汇报。
3. `review`：调用 wudi-reviewer 子代理评审当前未提交改动（`git diff`）或用户指定文件，输出 P0~P3 分级意见；无改动时说明。
4. `test`：盘点项目现有测试（框架、覆盖范围、能否跑通），跑一遍并汇报；核心路径缺测试的列补测建议。
5. `refactor`：先小步验证当前行为有测试兜底（没有先补特征测试），再按「方案确认 → 小步重构 → 每步验证」推进，禁止大爆炸式重写。
